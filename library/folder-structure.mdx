How you organize the Library matters more than which structure you pick. Any folder structure works well, as long as each folder is specific enough that you (and the AI) can point at exactly the right one when searching.

## The rule: subfolders over mega-folders

* **Keep folders under roughly 20 files.** When one grows past that, split it into subfolders.
* **Folders within folders is good.** A mega-folder with 100+ files is not.
* **Why:** when a search is scoped to a folder (see the [Prompting Guide](/prompting-guide)), a small, specific folder means the AI reads only the relevant files, so answers come back faster, more accurate, and easier to verify.

## Why the example works

* **One job per folder.** When each folder holds one kind of content, the AI (and your teammates) always know where to look, and where new files belong.
* **Names carry the facts.** Contract numbers, date ranges, and win/loss outcomes in folder names make search results self-explanatory and let you scope AI requests precisely: "search the 02_Past-Performance folder for cloud migration work."
* **Submitted work stays frozen.** Separating the never-edited record (`03_Proposal-Library`) from reusable excerpts (`_Reference-Content`) means you can reuse confidently without corrupting the archive.
* **No folder gets huge.** Every branch bottoms out in small, specific folders, which is the rule that makes everything else work.
